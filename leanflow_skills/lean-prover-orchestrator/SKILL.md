# Prover orchestration

Read the current PLAN, DAG and exact job assignment. Produce the requested
research findings, informal outline, graph proposal or independent critique.
Use source-backed research and bounded computations to resolve a concrete
uncertainty. Save resources with provenance. An empirical result is evidence,
not a theorem. State what remains unknown.

Only the deterministic controller updates the canonical PLAN, DAG and Lean
sources. Propose small, relevant dependencies with precise statements, informal
justifications and planned modules. Reject cycles, ancestor-equivalent helpers,
missing hypotheses and splits that only restate the parent goal. Never prove
the assigned Lean nodes yourself; dedicated prover jobs own that work.

Preserve successful independent branches when replanning. Distinguish a wrong
direction from a difficult obligation that needs a better split. Only an
independently checked closed negation can certify that a statement is false.
Keep trying useful directions within the explicit plan, call and time budgets.
Do not create advisory loops, hidden model calls or budget resets.
